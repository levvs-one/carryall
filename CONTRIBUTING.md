# Contributing

Спасибо за интерес к Carryall. Для этого проекта важнее корректность файлового поведения, чем количество функций.

## Перед изменением

Убедитесь, что сценарий сохраняет основные инварианты:

1. исходники не изменяются;
2. существующий результат не перезаписывается;
3. неполная запись не получает финальное имя;
4. готовый результат повторно читается и проверяется;
5. небезопасные/неоднозначные пути отклоняются.

## Локальная проверка

На Windows с .NET SDK из `global.json`:

```powershell
dotnet restore Handinpack.sln --locked-mode
dotnet build Handinpack.sln -c Release --no-restore
dotnet test --solution Handinpack.sln -c Release --no-build
dotnet run --project src\Carryall.Cli\Carryall.Cli.csproj -c Release --no-build -- --version
```

`TreatWarningsAsErrors` включён глобально. Не отключайте analyzer только ради зелёной сборки без объяснения причины.

## Тесты

Для изменений файлового ядра добавляйте тест, который работает с реальными временными файлами или ZIP. Особенно важны отрицательные сценарии: коллизии путей, изменение исходника, отмена, повреждённый manifest, ссылки и лимиты.

## Совместимость формата

`handinpack.json` schema version 1 уже опубликована. Изменения, которые делают старые комплекты непроверяемыми, должны рассматриваться как отдельная версия формата и отдельное решение, а не как случайный refactor.

## Pull request

PR должен коротко отвечать на три вопроса:

- что меняется для пользователя;
- какой инвариант/риск затрагивается;
- каким тестом это проверяется.
