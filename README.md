# Handinpack

Комплект к передаче, который можно проверить.

Handinpack собирает выбранные файлы в новую папку или ZIP, добавляет читаемую опись и проверяет записанные копии по SHA-256. Имена и состав можно подготовить заранее. Исходные файлы приложение не переименовывает, не перезаписывает и не удаляет.

Это локальное Windows-приложение с русским интерфейсом. Оно подходит для передачи чертежей, материалов проекта, приложений к письму и других наборов файлов, где важно не забыть нужное и не отправить лишнее.

Для версии 0.1 используйте обычные локальные диски. Рецепты не открывают сетевые пути автоматически. Это не означает полного запрета сети: системный диалог позволяет пользователю явно выбрать сетевое место, а прямой выбор сетевых источников не прошёл полный набор проверок.

## Переносная версия

Windows x64: [сборки и контрольные суммы](https://github.com/levvs-one/handinpack/releases). Распакуйте архив целиком в отдельную папку и запустите `Handinpack.exe`. Не переносите один EXE без соседних файлов. В переносной сборке есть .NET 10 runtime; устанавливать SDK для неё не нужно.

Сборка не подписана сертификатом издателя. Если Windows сообщает о неизвестном издателе, проверьте источник и контрольную сумму; приложение не меняет настройки безопасности. Архив не является установщиком и не добавляет автозапуск.

## Запуск из исходников

Нужны Windows, PowerShell и .NET SDK **10.0.400** либо более новый патч той же ветки `10.0.4xx`. Правило выбора SDK задано в [global.json](global.json). Для запуска WPF-приложения нужен Windows Desktop runtime .NET 10; SDK для Windows включает его.

Из корня репозитория:

```powershell
dotnet restore Handinpack.sln --locked-mode
dotnet build Handinpack.sln -c Release --no-restore
dotnet run --project src\Handinpack.App\Handinpack.App.csproj -c Release --no-build
```

Приложение и файловое ядро используют WPF и стандартную библиотеку .NET. Внешние пакеты нужны тестовому проекту, а не работе с комплектами. Первый `restore` может потребовать доступ к NuGet.

## Первый комплект

1. Нажмите **«Добавить файлы»** или **«Добавить папки»**, либо перетащите материалы в окно. В описи появятся исходные пути и будущие имена копий.
2. Укажите название, формат и существующую папку результата вне исходных папок. Если опись показывает проблему, измените путь копии или исключите позицию с причиной. При необходимости раскройте требования к комплекту.
3. Нажмите **«Собрать и проверить»**. Дождитесь сообщения **«Комплект проверен»**, затем откройте место результата кнопкой **«Показать результат»**.

Внутри результата будут выбранные файлы, `contents.txt` для чтения человеком и `handinpack.json` с путями, длинами и хешами. Итоговое имя появляется только после повторного чтения и проверки записи. Существующие результаты не заменяются.

## Что можно подготовить

- Изменить имя или относительный путь копии, не меняя исходник.
- Исключить материалы с объяснением и оставить это объяснение в описи.
- Задать допустимые расширения, обязательные пути и отдельные лимиты на один файл, все материалы и готовый результат с описями.
- Сохранить локальный рецепт набора и заново прочитать исходники при следующей передаче.
- Проверить существующий Handinpack-комплект без распаковки ZIP и без исправления его содержимого.

## Что означает «проверен»

Записанные байты совпали с длинами и SHA-256 из описи; лишние и недостающие файлы не обнаружены. Это проверка согласованности комплекта, **не цифровая подпись, проверка автора или антивирус**. Тот, кто может заменить и файлы, и опись, может создать другой согласованный комплект.

Handinpack не делает VSS-снимок каталога. Остановите запись в исходные файлы перед сборкой. Ссылки, junction и облачные заполнители не поддерживаются. Пустые папки не передаются; пустые файлы передаются.

При ошибке или отмене промежуточная запись может остаться рядом с выбранным результатом под именем `.handinpack-<идентификатор>.incomplete`. Программа сообщает её путь и не удаляет автоматически. Такой объект не является готовым комплектом.

## Проверка кода

После восстановления зависимостей:

```powershell
dotnet test --solution Handinpack.sln -c Release --no-restore
```

Тесты работают с реальными файлами и ZIP: сверяют независимые хеши, изменения исходников, отказ от перезаписи, отмену во время чтения и записи, повреждённые описи, неоднозначные пути и ссылки. Есть отдельный сценарий с 10 000 небольших файлов. Это не обещание пропускной способности на любой машине или гарантированной вместимости формата.

Тестовые данные создаются во временных каталогах. Для другого тома задайте `HANDINPACK_TEST_ROOT`; Windows-тесты junction используют отдельный каталог на системном томе, поддерживающем такие ссылки.

## Устройство проекта

- `src/Handinpack.App` - окно WPF, системные диалоги, локальные рецепты.
- `src/Handinpack.Core` - планирование, запись, проверка и формат описи.
- `tests/Handinpack.Tests` - проверки файлового поведения на MSTest.
- `tests/Handinpack.App.Tests` - ввод, рецепты и восстановление состояния окна после ошибок.

Ограничения объёма, памяти при чтении ZIP, метаданных и файловой системы перечислены в [справочнике формата](docs/format.md#ограничения).
