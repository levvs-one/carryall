# Security

## Модель безопасности

Carryall предназначен для локальной подготовки и проверки комплектов файлов.

Проверка подтверждает **внутреннюю согласованность**: набор файлов, размеры и SHA-256 должны совпадать с `handinpack.json`, а `contents.txt` проверяется по собственной длине и SHA-256 из manifest.

Это не доказательство авторства и не цифровая подпись. Если злоумышленник может заменить одновременно payload и manifest, он может создать другой согласованный комплект.

## Что Carryall старается предотвращать

- Path traversal и абсолютные пути внутри комплекта.
- Неоднозначные Windows-пути и зарезервированные имена.
- Коллизии с учётом регистра и Unicode normalization.
- Symlink/junction/reparse-point и cloud-placeholder источники.
- Публикацию результата, если исходник изменился после сканирования.
- Тихую перезапись существующего результата.
- Выдачу частично записанного объекта за готовый.
- Лишние, отсутствующие и повреждённые записи при верификации.
- Неконтролируемо большие manifest, payload и число файлов.

## Не является

Carryall не является антивирусом, sandbox, системой электронной подписи, системой разграничения доступа или VSS snapshot-механизмом.

Программа читает выбранные пользователем локальные файлы и записывает новый локальный результат. Перед сборкой следует остановить изменения исходных файлов.

## Проверка релизов

Официальные релизы публикуются в GitHub Releases вместе с `SHA256SUMS.txt`. Бинарники 0.2.0 не подписаны коммерческим code-signing сертификатом издателя.

## Сообщить об уязвимости

Не публикуйте рабочий exploit или чувствительные данные в публичном issue.

Для безопасной первичной фиксации проблемы создайте минимальное описание без секретов: затронутая версия, тип входных данных, ожидаемое и фактическое поведение. Если воспроизведение требует чувствительных материалов, сначала запросите приватный канал у владельца репозитория через профиль GitHub.

Особенно полезны отчёты о:
- обходе проверки путей;
- неожиданном следовании reparse point;
- публикации непроверенного результата;
- расхождении между manifest и фактически принятым содержимым;
- resource-exhaustion обходах установленных лимитов.
